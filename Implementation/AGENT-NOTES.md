# Agent Notes (living file; orchestrator-maintained)

Practical facts every implementation agent needs. Read after `00-README.md`, `05-Conventions.md`, `06-Agent-Protocol.md`. Add a bullet when you hit something the next agent will hit too. Keep entries short.

## Environment
- Windows 11. .NET SDK 10.0.400 only; ASP.NET runtime 10.0.11. `dotnet-ef` 10.0.5 installed globally.
- SQL Server: only LocalDB (`(localdb)\MSSQLLocalDB`) on this machine. Tests default to it; `TEST_SQL_CONNECTION` overrides.
- No `wasm-tools` workload. Do not install workloads. IL trimming works without it; AOT would not.
- No CFBD API key is available. ESPN public scoreboard is reachable without a key. Use fixtures for all development.
- Manual device checks (iPhone install, real Google login, real push) cannot be done by agents. Do everything else, document the exact operator steps, and record the item as `Manual pending (operator)` in STATUS.md notes. Never claim a manual check passed.

## Git workflow
- `main` is the integration branch. Parallel agents work in **git worktrees** on task branches `p<phase>-<task>-<slug>`. Agents do **not** merge to `main`; report `BRANCH: <name> @ <commit>` and the orchestrator merges.
- Conventional Commits; every commit ends with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- `.gitattributes` stores LF, checks out CRLF. `.editorconfig` demands CRLF; run `dotnet format` before committing or `dotnet format --verify-no-changes` fails with ENDOFLINE.
- Run plain `dotnet format` (never `dotnet format --no-restore`): without restore it compiles against unresolved references and silently strips `using` directives from unrelated files.
- Migrations: append-only, named `Phase<N>_<Task>_<What>`. Never edit another task's migration.
- `src/NcaafPickEm.Infrastructure/Data/Migrations/.editorconfig` marks that folder as generated code. Without it `dotnet ef migrations add` fails the next build on IDE0161/IDE0005. Do not hand-write code there and do not reformat what EF emits.

## Build strictness (from P0-01)
- `TreatWarningsAsErrors` + `EnforceCodeStyleInBuild` + `GenerateDocumentationFile` are on. An unused `using` is a build **error** (IDE0005). Private instance fields `_camelCase`; private static fields `PascalCase`.
- Central Package Management: add a `PackageVersion` to `Directory.Packages.props` and a version-less `PackageReference` in the csproj. A `Version` attribute in a csproj fails restore (NU1008). Match ASP.NET package versions to runtime 10.0.11.
- Pinned: xunit 2.9.3, FluentAssertions 7.2.2 (do not upgrade to 8), Serilog.AspNetCore 10.0.0, Mvc.Testing 10.0.11.

## Auth (from P0-03)
- Scope a league endpoint group with `RequireLeagueMember()` or `RequireLeagueCommissioner()` from `Api/Auth/LeagueAuthorizationExtensions.cs`, then read the membership back with `HttpContext.GetMembership()`. Never re-query the membership in a handler. Non-member is 404, member-on-commish is 403.
- The CSRF filter is on the whole `/api` group already; do not add it per endpoint. Mutations need `X-Requested-With: NcaafPickEm`.
- Signed-in identity is `ICurrentUser` (scoped). Claims are `ClaimTypes.NameIdentifier` = our `Users.Id`, `Name` = display name, `Email`.
- API tests: `[Collection(ApiTestCollection.Name)]`, take `ApiTestFixture`, seed with `TestUsers`, call `factory.CreateClientAs(userId)` (or `CreateMutatingClientAs` for the CSRF header). One authorization-matrix test per endpoint group: `AuthMatrix.RunAsync(fixture, method, memberRoute, commishRoute)` with `{leagueId}` in the templates.
- `/api/leagues/{leagueId}/ping` and `/ping/commish` are gone (P1-01, D-021): `DiagnosticsEndpoints.cs`/`DiagnosticsPing.cs` are deleted and `AuthMatrixTests` runs against the real `LeagueEndpoints`/`InviteEndpoints` routes instead. `AuthMatrix.RunAsync` now takes an optional `commissionerMethod` so a member `GET` route can pair with a commissioner route that answers a different verb (`PUT .../settings`), D-041.
- **Do NOT put `#[.{fingerprint}]` placeholders back in `Web/wwwroot/index.html`** (D-024). The SDK only rewrites them when the Web project is published on its own; through the Api's publish the literal placeholder ships and the app never boots. `OverrideHtmlAssetPlaceholders` is false on purpose.
- **Do NOT set `TrimMode=full`** on the Web project (D-025): it strips component constructors reached only by reflection, so a published build renders `NotFound` and throws `CtorNotLocated`. The SDK default trim mode is what we ship.
- A publish that curls clean can still be a dead app. After any change to `index.html`, trimming, or publishing, actually render the app in a browser. Headless Edge works: `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`; `--dump-dom` fires before WASM boots, so drive it over the DevTools protocol (`--remote-debugging-port`) and poll for real content. P0-04 left a working harness recipe in `Implementation/spikes/wasm-load-time.md`.

## Jobs (from P0-06)
- Everything scheduled lives in `src/NcaafPickEm.Infrastructure/Jobs/`. One `BackgroundService` (`JobScheduler`) calls `SchedulerTick.TickAsync(nowUtc, ct)` every minute; `TickAsync` holds all the logic so tests never wait on the wall clock. `Jobs__Enabled=false` makes the hosted service log one line and return (`ApiFactory` already sets it).
- **Add a cron job**: implement `IScheduledJob` (`Name`, `CronExpression`, `RunAsync(scheduledFor, ct)`) in `Infrastructure/Jobs/`, then one `services.AddScheduledJob<YourJob>();` line in `Infrastructure/DependencyInjection.cs`. Jobs are scoped, so `AppDbContext` is fine to inject. Cron is a standard **five-field** expression evaluated in **Eastern** (`SeasonCalendar.Eastern`) by Cronos — write `30 23 * * *` for 11:30 PM ET and let the scheduler do the DST maths.
- **Add a one-shot** (a due time that lives in the database, like the week lock or the Saturday reminder): implement `IOneShotJob` — `Name`, `GetDueAsync(nowUtc, ct)` returning `OneShotOccurrence(Key, DueUtc)`, and `RunAsync(occurrence, ct)` — then `services.AddOneShotJob<YourJob>();`. This is the card's `IOneShotScheduler` (D-034). Answer the naive query and stay stateless: the tick drops occurrences dated after `nowUtc` and skips ones already recorded.
- Idempotency is the `JobRuns(JobName, ScheduledForUtc)` unique index. The tick inserts the row **before** running and treats a duplicate key as "someone else has this one". A one-shot's row is `JobName = "{Name}:{Key}"`, so name + `:` + key must fit 60 characters. **Write every job to be safely re-runnable** (D-033): a crash between claim and finish, or the catch-up window, can offer the same occurrence again.
- Catch-up is bounded to `Jobs__CatchUpMinutes` (60). A job that has never run starts its window 60 minutes back, so a fresh database logs up to twelve heartbeats on first boot.
- **Testing**: build a container over the test database with `SchedulerHarness.Create(fixture, services => services.AddScoped<IScheduledJob>(_ => job))` and drive `harness.Tick.TickAsync(anyInstant, ct)`. `SchedulerHarness.CronForMinuteOf(instant)` pins a cron to one Eastern minute, `UniqueJobName(prefix)` keeps the shared database's `JobRuns` table collision-free, `ReadRunsAsync(name)` reads the rows back. `RecordingScheduledJob` / `RecordingOneShotJob` count invocations. See `JobSchedulerTests` and `OneShotTests`.
- `HeartbeatJob` (`*/5 * * * *`) is proof of life and owns no table. `GET /api/admin/data-status` shows the last 50 runs; scope an admin route with `RequireAnyLeagueCommissioner()` (403, not 404, for a non-commissioner — D-035).

## Leagues (from P1-01)
- `Domain/Leagues/LeagueRules` is the pure invariant layer: `ValidateName`, `ValidateWeekRange` (against `IReadOnlyList<SeasonWeek>`), `EnsureRoomForNewMember` (cap 50), `EnsureNotActingOnSelf`, `EnsureAtLeastOneCommissionerRemains`, `ApplyTransfer` (mutates the two `Membership` objects it is given; never touches a third), `ValidateDisplayNameOverride`. Every check throws `LeagueRuleViolation` (a `Code` + message); `Api/Endpoints/LeagueRuleViolationResults.ToProblem()` maps the code to 400 or 409 `ProblemDetails`. Add a new rule here, not in the service.
- `Infrastructure/Services/LeagueService` and `InviteService` (both `AddScoped`, both take `AppDbContext`) own every league/membership/invite operation; `Api/Endpoints/LeagueEndpoints.cs` and `InviteEndpoints.cs` are thin — resolve `HttpContext.GetMembership()`, call one service method, catch `LeagueRuleViolation` and return `.ToProblem()`. `MeEndpoints.ToResponse` calls `LeagueService.ListMineAsync` for `MeResponse.Leagues` — do not duplicate that query.
- **Effective per-league display name**: always go through `Domain/Leagues/MemberNameProjection` — `.Selector` is an `Expression<Func<Membership, string>>` for a LINQ `Select` (EF pushes `DisplayNameOverride ?? User.DisplayName` into SQL), `.Effective(membership)` is the same rule for an already-loaded entity (needs `.Include(m => m.User)`). Every DTO that carries a member name (`MemberRow` today; P1-03's other surfaces, the dashboard, the leaderboard later) must use one of these two, never `?? ` by hand, or the two will drift.
- Uniqueness on `PUT /api/leagues/{leagueId}/members/me/display-name` is checked case-insensitively against **active** members only (`RemovedUtc == null`) via `.ToUpper()` on both sides inside the EF query (not `StringComparison.OrdinalIgnoreCase`, which does not reliably translate to SQL) — a removed member's old name is free for anyone (see the `DisplayNameConflictTests` "removed member" case). Response is the caller's own updated `MemberRow` (D-039), not `LeagueDetail`.
- **Invite accept reactivates, never duplicates**: `Memberships` has a unique index on `(LeagueId, UserId)`, so a former member accepting a new invite has their existing row's `RemovedUtc` cleared and `JoinedUtc`/`JoinedWeek`/`Role` reset, rather than a second row (D-037). `InviteService.ResolveAsync` picks one `InviteState` when several apply: Revoked > Expired > AlreadyMember > Full (D-038). Invite codes are 8 chars from an unambiguous alphabet (no `0/O/1/l/I`) via `InviteCodeGenerator.Generate()` (`RandomNumberGenerator`); `InviteResponse.Url` is `{App:PublicOrigin}/join/{code}`, falling back to the request's own scheme+host when that config key is unset.
- **Seeding a league in a test**: `TestUsers.CreateLeagueScenarioAsync(factory)` (already existed from P0-03) gives you a league with a commissioner and a member plus a stranger with no membership — use it for anything role/auth shaped. For a bespoke roster, `TestUsers.CreateUserAsync`/`CreateLeagueAsync`/`CreateMembershipAsync` compose directly. **Never name a test league "Family League"** — that is `FixtureSeeder.DemoLeagueName`, seeded once per run in the same shared database, and `FixtureSeederTests`/`DevLoginTests` locate it by that name.
- **`MemberRow.IsMe`** (P1-03, additive): true when the row is the caller's own membership. `LeagueService.GetMembersAsync` now takes `callerUserId` to populate it; `Pages/Leagues/Members.razor` uses it to hide self-actions (remove/promote/demote/transfer) the server would 409 anyway and show a "You" tag, instead of the earlier "offer every action, let the 409 explain" approach.
- **Global-name collision rule** (P1-03, D-058): `PUT /api/me` rejects (409) a rename that would collide with another active member's *effective* name in a league where the caller has no per-league override. `LeagueService.ListGlobalNameCollisionsAsync(userId, newName, ct)` returns the colliding league names; `MeEndpoints.UpdateAsync` turns a non-empty result into a `LeagueRuleViolation(DisplayNameTaken)` before saving. Per-league uniqueness on `PUT .../members/me/display-name` is unchanged.
- **P1-01 review follow-ups landed by P1-03**: `LeagueService.ListMineAsync`/`GetMembersAsync` batch the season-weeks lookup (grouped by `SeasonYear`) and the `WeekSubmissions` lookup (one query into a dictionary keyed by `MembershipId`) instead of querying per membership. `LeagueRuleViolationCode.InvalidPointValue` (400) replaces the `InvalidWeekRange` misuse in `UpdateSettingsAsync`'s `DefaultPointValue` check. `LeagueRuleViolationCode.MembershipNotFound` (404) replaces `InvalidTransferTarget` (400) when `LoadActiveMemberAsync` cannot find the target — covers remove/promote/demote/transfer alike, since they all funnel through it. `LeagueService`'s remove/promote/demote/transfer and `InviteService.AcceptAsync` now log an `Information` line (actor, target, league) via constructor-injected `ILogger<T>`.
- **Deterministic "current week" in a test**: `fixture.PinnedFactory` (added by P1-01 alongside `Factory`/`CookieFactory`) is a second `ApiFactory` sharing the run's database with its `TimeProvider` fixed at `ApiTestFixture.PinnedNowUtc` (2026-10-14T12:00Z = week 7 of the fixture calendar, `ApiTestFixture.PinnedCurrentWeek`). Pass a `TimeProvider` to `new ApiFactory(connectionString, timeProvider: ...)` for any other fixed instant; it registers with a plain `AddSingleton` in `ConfigureTestServices`, which runs after `AddInfrastructure`'s `TryAddSingleton(TimeProvider.System)` and wins (D-042).

## Domain events (from P2-03)
- Events are records in the feature folder that owns them (`Domain/Seasons/Events/GameWentFinal`, `GameScheduleChanged`), implementing `Domain/Events/IDomainEvent`. **Define a new one**: `public sealed record WeekLocked(...) : IDomainEvent { public DateTime OccurredUtc { get; init; } }`. `OccurredUtc` is an `init` property, not a constructor parameter — the Domain project has no clock, so the raising service sets it (D-046). The names `01-Architecture.md` reserves and nobody has built yet: `GameAddedToSet`, `GameRemovedFromSet` (P3-04/P4-04), `WeekLocked` (P4-02), `ResultOverridden`, `GameVoided` (P5-02).
- **Raise one**: inject `DomainEventCollector` (scoped) and `IDomainEventDispatcher`, then mutate → `collector.Raise(new GameWentFinal(...) { OccurredUtc = nowUtc })` → `SaveChangesAsync` → `dispatcher.DispatchAsync(collector.TakeAll(), ct)`. Always in that order: subscribers must see a database that already agrees with the event. `TakeAll` empties the collector so a second dispatch in the same scope re-delivers nothing.
- **Handle one**: implement `IDomainEventHandler<TEvent>` in `Infrastructure/` and add `services.AddDomainEventHandler<TEvent, THandler>();` in `Infrastructure/DependencyInjection.cs` (not a hot-spot edit — it is one line in the list every phase adds to). Several handlers per event is normal; they run sequentially in registration order.
- A handler that throws is logged and **skipped** — one subscriber can never block scoring — so a handler must not be the only thing keeping data correct. Write handlers idempotently: the event is dispatched after the save, so a crash in between loses it, and the nightly recompute is the real backstop.
- Test handlers with a plain `ServiceCollection` (`DomainEventDispatcherTests`). Services that raise events should also return them (`LiveScoreApplyResult.Events`) so a test can assert without subscribing.

## Live scores (from P2-03)
- One call per Eastern date. `ILiveScoreProvider.GetScoresAsync(easternDate)` → `LiveScoreUpdate` records; ESPN's `dates` parameter takes exactly one day (a range is HTTP 400) and buckets by **Eastern** date, so a Saturday call already contains the late game that goes final after midnight.
- **Do not inject `EspnLiveScoreProvider` or `CfbdLiveScoreProvider` directly.** With `Providers:LiveScores=Espn|Cfbd` the registered `ILiveScoreProvider` is `CompositeLiveScoreProvider`, which asks `ILiveScoreHealth` which source to call; with `Fixture` it is `FixtureLiveScoreProvider` and nothing ever switches.
- `ILiveScoreHealth` (singleton): `ConfiguredSource`, `ActiveSource`, `ConsecutiveFailures`, `ScoresMayBeStale`, `RecordSuccess()`, `RecordFailure()`, `ResetForNewDay()`. Three consecutive ESPN failures switch `ActiveSource` to Cfbd for the rest of the day and set `ScoresMayBeStale`; the composite records the outcome itself, so a caller only calls `ResetForNewDay()` when a game-day window opens. The dashboard banner (P6-02) reads `ScoresMayBeStale` — and should say what is missing, not just "stale": the CFBD fallback has no period, no clock, no live odds and no Postponed or Cancelled.
- **Applying scores**: `LiveScoreApplyService.ApplyAsync(easternDate, updates, ct)` does matching, persistence and events, and returns counts plus the events it raised. It loads candidate games for that Eastern date **and the day before** (D-049), so a poll issued after midnight still finds Saturday's late game. Safe to re-run: the same snapshot twice changes nothing and raises nothing.
- `GameWentFinal` fires once per game, carries the **provider** week (so a post-midnight finish scores against the right week), and has a null `WinnerTeamId` on a tie — that is "needs review", not a win. `GameScheduleChanged` fires into and out of Postponed/Cancelled.
- Matching lives in `Providers/GameMatcher` + `TeamNameIndex` + `TeamNameNormalizer`; the rules (and why an FCS game on our own schedule still gets scores) are `04-Domain-Algorithms.md` section 9. If a real payload ever matches wrongly, add a `TeamAliases(Source=Espn)` row rather than loosening the normalizer.
- Every outbound provider call goes through `IProviderCallRecorder.RecordAsync(provider, operation, call, ct)` so `ProviderCalls` has a row either way. Never call a provider's `HttpClient` around it.
- The P2-01 captures in `tests/NcaafPickEm.Fixtures/Real/` are embedded: `FixtureLoader.ReadRealText("espn-scoreboard-20260912.json")` / `ReadReal<T>`. `FixtureLoader.Names` still lists only the synthetic `Data/` week.

- **Razor gotcha that cost real time**: a component attribute of `string` type is a plain string *literal* unless you prefix it with `@` — unlike non-string parameter types (enum, `DateTimeOffset?`, `bool`, ...), which Razor always compiles as a C# expression even without `@`. `Param="someVar"` silently renders the literal text `someVar` when `Param` is a string; you need `Param="@someVar"`. This does not show up as a build warning or error.
- **Don't inject `AuthenticationStateProvider`/`ApiAuthenticationStateProvider` from an ordinary page just to know "who am I".** Calling `GetAuthenticationStateAsync()` issues a real `GET api/me` through the shared `HttpClient`; a 401 there is caught by `UnauthorizedRedirectHandler` and silently navigates the whole page away to `/login`, which is surprising when the only reason you wanted "me" was a cosmetic hide (e.g. "don't show a self-remove button"). Prefer a server-driven answer (a field on the DTO) or, failing that, let the server's own invariant reject the action with a 409 you surface in an `ErrorBanner`.
